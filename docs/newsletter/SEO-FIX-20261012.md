# Newsletter SEO repair — local validation, not released

Baseline: `17f1c20c23275ae58f7e8552b08e4db9829f3dc5`.
Branch: `fix/newsletter-seo-20261012`.

The early release document described `/newsletter` as a demo. The later
`KIT-INTEGRATION-20261006.md` and current router establish `/newsletter` as the
live signup page and `/newsletter/demo` as the separate safe demo. The old
unconditional component robots effect therefore no longer matches the page.

## Change

- `/newsletter`: canonical `https://dailycosmos.net/newsletter`, `index, follow`.
- `/newsletter/demo`: its own canonical, `noindex, nofollow`.
- `/newsletter/first-ai-card`: its own canonical, `noindex, nofollow`, preserving
  the existing preview restriction and all resource behavior.
- One metadata policy supplies the built initial HTML and SPA route changes,
  including browser back and hash entry points. Vite's compiled shell and hashed
  assets are reused; no forms, subscriber data or draft content are prerendered.
- Explicit Vercel rewrites select the three route shells ahead of the existing
  fallback. `buildCommand` explicitly invokes the updated build script so an
  older dashboard override cannot omit shell generation.
- Sitemap adds only the live newsletter page. No demo/card/draft indexing is
  opened, and no draft or membership content is changed.
- Exact `/content` and `/content/` redirect to `/` permanently (Vercel 308).
  These are homepage aliases in this baseline: the router has no content route
  and falls through to Home; the existing catch-all serves index.html. No
  `/content/*` wildcard or unknown historical article redirects are added.
