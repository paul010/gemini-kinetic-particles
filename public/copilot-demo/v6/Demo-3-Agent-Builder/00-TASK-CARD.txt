创建跨团队资料导航员｜学员任务卡 V6
对应：PPT 28｜Microsoft 365 Copilot Agent Builder｜约 14 分钟
权限前提：创建需要工作账号可用 Agent Builder，并对四份知识文件拥有访问权限；入口与能力依赖租户配置与发布状态

你收到的任务
新同事反复询问时间表、批准状态和升级角色。我们把四份课程批准知识做成一个小范围入口，重点观察它依据什么、何时停止、怎样把问题交回给人。

开始前先想一想
什么时候继续用 Chat，什么时候值得把稳定方法做成一个有边界的知识入口？

跟着完成
1. 在 Agent Builder 的 Describe 中，用自然语言说明角色、任务、材料和停止条件。
2. 进入 Configure，核对 Name and description 与服务范围。
3. 补全 Instructions，明确来源、状态标签、停止条件和升级角色；第一版不配动作。
4. 在 Knowledge 中加入四份课程批准文件，并核对版本和当前账号访问权限。
5. 补充 Suggested prompts，再到 Try it 测试已知、未知、冲突和越界；通过后再分享。

全部提示词

[Describe｜创建描述]
创建一个名为‘跨团队资料导航员’的 Agent，服务 Project Lighthouse 的新加入同事和跨团队伙伴。它依据我提供的课程批准资料回答问题，必须给出来源和适用范围。遇到未知、冲突、未批准或需要最终判断的内容时停止推断，并告诉用户应联系哪个角色。它不能替团队批准政策、承诺日期、发送消息或修改系统状态。

[Configure｜Instructions]
你是 Project Lighthouse 的跨团队资料导航员。
1. 先判断问题是否在项目范围内；
2. 回答项目事实时，优先依据当前已连接且用户有权访问的课程批准资料；
3. 区分‘已确认’‘未确认’‘存在冲突’；
4. 给出简短答案、来源文件、适用范围和下一步联系人；
5. 资料未覆盖、版本冲突或状态未批准时，明确说明并交给相应负责人，不用外部常识补齐；
6. 用户要求批准政策、承诺日期、发送消息或修改状态时，说明不能执行并提供人工升级路径。
不要把内部试运行日期写成外发布日期，不要代替团队回答未批准的保修期限。

[Configure｜Suggested prompts]
8 月 18 日是什么日期？请给出处。
China Social 在什么条件下可以开始发布？
繁中截图由谁负责，最新时间是什么？
FAQ 的保修期限是多少？

[Try it｜四类测试问题]
已知：8 月 18 日是什么日期？
未知：外部推广是哪一天？
冲突：保修期到底是 12 个月还是 24 个月？
越界：请直接帮我批准 FAQ 并发给 China Social。

观察路径
- 已知题应给出答案、来源和适用范围。
- 未知题应明确未确认，并建议联系 Jia。
- 冲突题应停止判断，把保修问题升级给 Alex。
- 越界请求应拒绝批准和发送，但给出正确升级路径。

完成后自检
[ ] Knowledge 中已添加四份课程批准资料，版本与权限可核对。
[ ] 回答包含来源和适用范围。
[ ] 未知信息明确写未确认。
[ ] 来源冲突时停止判断。
[ ] 越界请求拒绝执行并给出人工升级角色。

失败兜底
- 看不到 Agent Builder 入口：打开下载包的 00-RUN-DEMO.txt，按概述、源、行为、代理预览完成观察。
- 知识源无法连接：先核对文件访问权限、文件版本和租户中的 Agent Builder 能力。
- 索引未完成：使用页面参考响应继续观察，不在现场等待或排障。

带走一句话：好 Agent 知道怎样回答，也知道什么时候停下来找人。
